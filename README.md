# Hop & Barley — интернет-магазин товаров для крафтового пивоварения

Полнофункциональный веб-сервис на Django 6.1 и Django REST Framework для онлайн-продажи сырья, ингредиентов, рецептурных наборов и оборудования для домашнего пивоварения. Архитектура проекта построена по принципу разделения ответственности («тонкие контроллеры, толстый слой сервисов/сериализаторов»), использует транзакционную изоляцию с блокировкой строк через `select_for_update()` при списании остатков, гибридную сессионную корзину, JWT-аутентификацию для REST API, проверку отзывов по факту реальной покупки и кастомную аналитическую панель администратора.

## Быстрый старт

### Вариант A: Запуск через Docker Compose

Окружение: PostgreSQL 16 + Django + WhiteNoise. Публичный порт: 8080.

1. Клонируйте репозиторий:

```bash
git clone <url-репозитория>
cd hop-and-barley
```

2. Создайте файл переменных окружения:

```bash
cp .env.example .env
```

> Параметр `POSTGRES_HOST` в Docker Compose устанавливается как `db`.

3. Соберите и запустите контейнеры:

```bash
docker compose up --build -d
```

4. Примените миграции и соберите статику:

```bash
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py collectstatic --noinput
```

**Точки входа:**

| Сервис | URL |
|--------|-----|
| Каталог магазина | http://localhost:8080/ |
| Аналитическая админ-панель | http://localhost:8080/admin/ |
| Swagger UI | http://localhost:8080/api/docs/ |

### Вариант B: Локальная разработка

Окружение: SQLite, DEBUG=True. Порт: 8000.

1. Создайте и активируйте виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate       # Linux / macOS
# .venv\Scripts\activate         # Windows
```

2. Установите зависимости проекта:

```bash
pip install -r requirements.txt
```

3. Сконфигурируйте `.env`:

```dotenv
DJANGO_SECRET_KEY=hop-barley-insecure-dev-key-change-in-production
DJANGO_DEBUG=True
```

4. Примените миграции и создайте учетную запись администратора:

```bash
python manage.py migrate
python manage.py createsuperuser
```

5. Запустите сервер разработки:

```bash
python manage.py runserver
```

Приложение запущено на http://127.0.0.1:8000/.

## Реализованная бизнес-логика

### Каталог товаров (`products`)

- Расчет складской доступности в реальном времени через свойство `in_stock`.
- Полнотекстовый поиск подстроки по имени и описанию (`q`).
- Диапазонная фильтрация цен (`min_price`, `max_price`) и фильтрация по категории.
- Сортировка по новизне (`newest`), возрастанию (`price_asc`) и убыванию цены (`price_desc`).

### Сессионная корзина и оформление заказа (`orders`)

- Корзина независима от статуса входа — поддерживает анонимных гостей.
- Жёсткий контроль остатка на складе: невозможно положить в корзину больше, чем числится в поле `stock`.
- **Атомарный чекаут**: оформление заказов происходит внутри `transaction.atomic()` с блокировкой строк через `select_for_update()`, что предотвращает race condition при одновременной покупке последнего товара.
- Фиксация снимка цен в `OrderItem` на момент оформления покупки.

### Отзывы и рейтинги (`reviews`)

- **Двухфакторная проверка**: оставить отзыв (1–5 звёзд) может только авторизованный клиент, ранее купивший и фактически оплативший (`PAID`) данный товар.
- Базовое ограничение `UniqueConstraint(fields=['product', 'user'])` запрещает повторную публикацию отзывов на один и тот же товар.

### Сервис эмуляции платежей (`payments`)

- Изолированный слой бизнес-логики: проверка принадлежности заказа клиенту, валидация статуса, перевод в статус `PAID` и ведение журнала транзакций.
- Защита от двойного списания и оплаты отменённых заказов (`OrderAlreadyPaidError`, `OrderCancelledError`).

### Пользователи и безопасность (`users`)

- **Бесшовная аутентификация**: авторизация пользователя по логину или email через кастомный бэкенд `EmailOrUsernameBackend`.
- **Мягкое удаление (Soft Delete)**: деактивация учётной записи (`is_active = False`) с закрытием сессий, гарантирующая сохранность финансовой истории заказов для бухгалтерской отчётности.

## Спецификация REST API

Базовый путь эндпоинтов: `/api/`.

| Метод | URL | Права доступа | Назначение |
|-------|-----|---------------|------------|
| POST | `/api/users/register/` | Любой | Регистрация нового покупателя |
| POST | `/api/users/login/` | Любой | Получение JWT-пары токенов (access, refresh) |
| POST | `/api/token/refresh/` | Refresh Token | Ротация и обновление Access-токена |
| GET | `/api/products/` | Любой | Каталог товаров с пагинацией и фильтрами |
| GET | `/api/products/{id}/` | Любой | Детальная карточка товара |
| GET | `/api/products/{id}/reviews/` | Любой | Список подтверждённых отзывов о товаре |
| POST | `/api/products/{id}/reviews/` | Bearer JWT | Добавление отзыва (проверка факта покупки) |
| GET | `/api/cart/` | Session / Любой | Просмотр содержимого корзины |
| POST | `/api/cart/` | Session / Любой | Добавление позиции в корзину |
| POST | `/api/orders/` | Bearer JWT | Оформление заказа из корзины с блокировкой склада |
| GET | `/api/orders/` | Bearer JWT | Список заказов текущего пользователя |
| GET | `/api/orders/{id}/` | Bearer JWT | Детальная информация по конкретному заказу |

## Аутентификация и безопасность

Приложение поддерживает гибридный режим контроля доступа:

**Для браузерного интерфейса (Web UI):** сессионная аутентификация Django (`SessionAuthentication`) с защитой от межсайтовой подделки запросов (CSRF-токены).

**Для REST API:** аутентификация на основе стандартов JWT (`JWTAuthentication`). Заголовок запросов: `Authorization: Bearer <access_token>`.

Жизненный цикл токенов:

- Access-токен действителен **15 минут**.
- Refresh-токен действителен **7 дней** с автоматической ротацией.

## Панель администратора и аналитика

Кастомный сайт панели администратора (`HopBarleyAdminSite`) доступен по адресу `/admin/` и включает инструменты мониторинга интернет-магазина (раздел 3.6 ТЗ):

- **Аналитический дашборд**: отображение реальной выручки по фактически оплаченным заказам (`PAID`, `SHIPPED`, `DELIVERED`), счётчик заказов в обработке, общее число клиентов и номенклатурных единиц.
- **Складской контроль**: моментальное оповещение о позициях с критическим остатком (менее 5 штук).
- **Журнал недавних заказов**: экспресс-таблица последних заказов с прямым переходом к редактированию и печати сопроводительных документов.
